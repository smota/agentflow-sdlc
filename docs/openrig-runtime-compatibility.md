# Pi runtime observation compatibility

AgentFlow currently has no registered publicly accepted and deployed Pi runtime observation
protocol. `adapters/openrig/runtime-capabilities.mjs` recognizes one local candidate solely to
inspect its separate readiness dimensions. Its result always has `compatible: false`; a
reported runtime version, compatible boolean, or matching configured model cannot change that.

The [#524 investigation and inline candidate patch](https://github.com/smota/agentflow-sdlc/issues/524#issuecomment-6201185481)
preserve the upstream baseline, local candidate commit, patch digest, reproduction and limits.
The isolated upstream candidate preserves ordinary process readiness and harmless prompting
while exposing catch-up failure separately. Actual selection comes only from RPC `get_state`
provider/model/thinking fields. A carried generation does not prove current occupant identity.
This candidate has not been published upstream, accepted as a public protocol, or installed.

The source fixture `adapters/openrig/__tests__/fixtures/pi-runner-observation-candidate-v1.json`
was generated by the candidate's actual `RunnerCore` with fake RPC replies and injected IO.
It omits session file paths and resume tokens. Its protocol wrapper in tests is an AgentFlow
candidate label, not an upstream public API declaration. Tests add explicit fake host identity
proof to exercise dimensions; the runner itself supplies no such proof.

`evaluateRuntimeCapabilities({runtime, report, expected, nowMs})` evaluates process readiness,
verified history, fresh actual provider/model/effort, externally verified current occupant
correlation, and activity-hook occupant correlation separately. Hook occupant mismatch is not
evidence of incompatible hook schema; `hookSchemaCompatibility` remains unknown. Missing
provider, stale model observation, invalid restore, unknown schema and unverified source do
not become valid through configured pins, version inference, or fresh collection timestamps.
No raw RPC error, path, token or model payload is echoed into the result.

Operational preflight accepts optional `runtimeCompatibility` entries shaped as `{seat,
report}`. It re-evaluates these raw reports against the intended contract and existing task
binding; caller booleans cannot bypass an unknown protocol. A supplied candidate-only,
unsupported, missing or duplicate seat report holds usability and admission. Omitting this
optional input preserves the existing trusted-host fixture interface; it does not upgrade the
compact live collector, which still cannot verify actual execution or admit work.

A future supported integration requires maintainer agreement on the public capability
contract, a deployed generation-bound reader, source freshness and identity verification,
and pinned before/after native or stub-assisted integration evidence. Registering or installing
that future support is separate work. No version is declared supported by this local change.
