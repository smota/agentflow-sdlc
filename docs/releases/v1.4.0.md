# AgentFlow SDLC v1.4.0 — Phase-zero bootstrap handoff

AgentFlow SDLC 1.4.0 lets a delivery run enter phase 0 from a declared predecessor. The requester records the opening request and owns its acceptance. The product manager remains the phase-0 delivery role and still sends the problem, outcome, and release intent onward.

## Enter phase 0 through a declared sender

The canonical catalog adds `agentflow:requester`. It is a bootstrap role with no lifecycle phase. It is not a tenth numbered phase, and it is not the exploratory QA sidecar. The requester sends the opening request only to `agentflow:product-manager`. Collaboration validation accepts that handoff because the catalog declares the edge.

A product-manager self-handoff, an unknown sender, and any undeclared edge stay rejected. Lifecycle phases stay 0 through 8. The handoff from product-manager to analyst is unchanged. Consuming projects adopt this catalog with the framework. They do not add a project-local inbound edge.

A run that starts at phase 0 advances when that handoff, the frozen contract, the candidate, and host-observed intent consent all belong to the run. Missing consent, a stale candidate, a delivery role for a later phase, or evidence for a different criterion still blocks advancement.

## Install and update

Node.js 20 or newer is required. For a runtime using npm for its global CLI installation:

```bash
npm install -g github:smota/agentflow-sdlc#v1.4.0
agentflow-sdlc doctor-env --target /path/to/your-project
agentflow-sdlc adopt plan --profile standard --target /path/to/your-project --json
```

Let your agent runtime resolve installation locations and shared skill management. Review the adoption plan before using `adopt apply` with its exact confirmation values; follow [assisted onboarding](../assisted-onboarding.md) and [run operations](../run-operations.md). Publishing this release does not update installed clients or migrate an already adopted catalog automatically. No npm-registry package is published by this release.

Projects that copied a 1.3.0 catalog need the updated role catalog before phase 0 can accept a handoff. Use `adopt plan` and review the requester role, the product-manager incoming edge, and the new transition before apply.

## Compatibility and validation

This is a minor release in the 1.x line. Existing consent, grants, writer fencing, human gates, and publication boundaries remain in force. The requester does not join the nine-phase workflow list, the high-assurance core role set, or the cockpit phase list.

Release readiness requires the repository product checks on Linux, Windows, and macOS with Node 20 and 24. The phase-0 regression calls the shipped catalog validator, collaboration verify and advance, and run advancement from a real phase-0 start. Those checks do not qualify a live consumer delivery run, and they do not supply consent for an existing local preview.

The changes since [v1.3.0](v1.3.0.md) were integrated through [#318](https://github.com/smota/agentflow-sdlc/pull/318), completing [#319](https://github.com/smota/agentflow-sdlc/issues/319).
