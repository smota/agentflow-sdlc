# AgentFlow SDLC v1.12.0 — Codex hooks load within the supported schema

AgentFlow SDLC 1.12.0 fixes a Codex startup error caused by an unsupported `agentflowSdlc` field in `.codex/hooks.json`. Codex hook files now use the supported root fields, so existing branch checks, formatting hooks, and session context can load again.

## Repair existing Codex settings

Settings merge no longer injects custom metadata into Codex hook files. It also removes legacy `agentflowSdlc` metadata explicitly owned by AgentFlow, while preserving hook definitions and descriptions. Preview remains read-only, applying a repair creates a backup, and repeating the merge leaves the repaired file unchanged. Foreign content is preserved.

Install the tagged version, then run these commands from each affected project:

```bash
npm install -g github:smota/agentflow-sdlc#v1.12.0
agentflow-sdlc settings merge --harness codex --dry-run
agentflow-sdlc settings merge --harness codex --apply
```

Reload Codex after applying the repair. Node.js 20 or newer is required. Installation uses the GitHub tag; this release does not publish an npm registry package.

## Earlier tagged capabilities included

The previous published GitHub Release was v1.9.0. This release also carries the capabilities already documented under the intervening tags: [v1.10.0](https://github.com/smota/agentflow-sdlc/blob/v1.10.0/docs/releases/v1.10.0.md) covers adaptive execution substrates, effort calibration, and the Lean 4-Seat default; [v1.11.0](https://github.com/smota/agentflow-sdlc/blob/v1.11.0/docs/releases/v1.11.0.md) covers the optional OpenRig 0.7.6 adapter and joining installed specs through the workspace catalog. These capabilities predate the Codex correction in this release.

## Compatibility and validation

This is the person-requested minor release; the Codex change is a backwards-compatible correction. Settings handling for Claude Code, Agy, and Pi is unchanged. OpenRig remains optional, with its existing 0.7.6 adapter floor.

Regression coverage exercises fresh Codex settings, existing metadata repair, preservation of hook content and foreign fields, backups, repeat application, and other harnesses. The hook validator now rejects unsupported top-level fields in the repository's Codex hook configuration.
