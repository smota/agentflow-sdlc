# AgentFlow SDLC v1.3.0 — Observable processes and qualified adoption

AgentFlow SDLC 1.3.0 helps teams observe delivery across sessions, connect an optional Meshloop runtime through a defined engineering interface, and adopt or resume the packaged workflow with clearer instructions. This minor release completes the bounded qualification work following 1.2.0.

## Observe delivery across sessions

Opt-in OpenTelemetry and offline capture now correlate runs, sessions and execution attempts, including source/target phases and roles. Attempted, acknowledged and failed events remain distinct, so observing an attempt does not imply that its transition was persisted. Offline analysis reports the records actually collected and leaves unavailable measurements unknown.

Qualification covers fresh-process continuation, actual OTLP export, disabled/offline collection and exporter failure. Telemetry remains advisory: it cannot grant authority, accept a phase or replace the durable audit record. Collection and shutdown have overhead; dropped records and missing terminal spans remain possible. This release makes no cost-reduction or universal performance guarantee. See [process observability](../process-autonomy/observability.md) and its [qualification evidence](../maintainers/process-observability-303-qualification.md).

## Connect Meshloop without making it a dependency

The optional public-CLI adapter binds a Meshloop graph to an admitted AgentFlow operation and candidate. A fresh process can observe and reconcile the existing graph without redispatching work. Successful results are checked against the configured binary digest, candidate ancestry, permitted paths and committed artifact bytes.

AgentFlow retains SDLC authority and acceptance; Meshloop retains technical planning, workers, worktrees and technical acceptance. The adapter does not call Meshloop's acceptance gate or apply returned changes to the caller's checkout. The direct execution path remains available without Meshloop configuration.

The qualified runtime is the pinned Windows Meshloop 0.2.0 build documented in the [integration guide](../process-autonomy/meshloop-minimal-integration.md). Tests used deterministic workers and real CLI/Git processes, including observation, timeout and cancellation. This does not qualify arbitrary binaries, operating systems or LLM coding quality. The initial output profile supports small regular-file additions and modifications; it is not a hostile-worker sandbox.

## Adopt and resume from the package

Public `handoff` and `resume` commands now dispatch through the existing run transport instead of failing before reaching it. Help and examples name the required writer identity, generation, plan digest and target-local input files. A packaged continuation trial resumed the same candidate in a fresh checkout at generation 1 without manual byte repair.

Adoption guidance clarifies runtime-owned installation, selective recovery, receipt-backed rollback and optional integration setup. Five bounded journeys cover fresh installation, partial/shared installation, old or unknown installations, governed continuation and optional integration. Required catalogued skills are checked in both source and package, preventing a missing skill from being silently skipped. Initial trial failures and corrections remain visible in the [adoption qualification](../process-autonomy/adoption-qualification.md); these results are not a universal host or zero-intervention guarantee.

## Install and update

Node.js 20 or newer is required. For a runtime using npm for its global CLI installation:

```bash
npm install -g github:smota/agentflow-sdlc#v1.3.0
agentflow-sdlc doctor-env --target /path/to/your-project
agentflow-sdlc adopt plan --profile standard --target /path/to/your-project --json
```

Let your agent runtime resolve installation locations and shared skill management. Review the adoption plan before using `adopt apply` with its exact confirmation values; follow [assisted onboarding](../assisted-onboarding.md) and [run operations](../run-operations.md). Publishing this release does not update installed clients or migrate project state automatically. No npm-registry package is published by this release.

## Compatibility and validation

This is a minor release in the 1.x line. Existing consent, grants, writer fencing, human gates and publication boundaries remain in force. Meshloop and telemetry are optional. Authenticated human identity, hard provider spending ceilings, broad model/host qualification and collector/dashboard installation remain outside this scope.

Release readiness requires `pnpm validate:release`, version consistency validation, and the release PR's Linux, Windows and macOS checks with Node 20 and 24. Automated product checks do not expand the live qualification claims above.
